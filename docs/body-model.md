# Модель тела: договор для замены на модель из Blender

Сейчас человек GoingBoy построен кодом (`web/js/body/procedural.js`). Позже его заменит модель,
сделанная в Blender со скелетом. Всё, что знает о теле ядро, лежит в `web/js/body/`, и модель
меняется без правок ядра, если выполнен этот договор.

## Что в `body/`

| Файл | Что | Меняется при замене |
|------|-----|---------------------|
| `skeleton.js` | имена костей, иерархия, позы покоя, суставы и пределы, массы, кожа капсулами | нет (это и есть договор) |
| `muscles.js` | 25 мышц на сторону: точки крепления в осях костей, сила, действие | нет |
| `procedural.js` | вид для three.js из капсул и лент | заменяется на `glb.js` |
| `retarget.js` | пересадка позы на скелет .glb с любыми осями костей | нет |

## Скелет

21 кость, имена ровно такие (правая сторона - `_R`, по правилу зеркала Blender):

```
pelvis
├─ spine ─ chest ─┬─ neck ─ head
│                 ├─ clavicle_L ─ upperarm_L ─ forearm_L ─ hand_L
│                 └─ clavicle_R ─ upperarm_R ─ forearm_R ─ hand_R
├─ thigh_L ─ shin_L ─ foot_L ─ toes_L
└─ thigh_R ─ shin_R ─ foot_R ─ toes_R
```

Точные начала и концы костей - `docs/skeleton.json` (выгружает `node tools/export-skeleton.js`).
Оси демки: метры, Y вверх, человек смотрит на +Z, его левая сторона +X. Рост 1.75 м, масса 70 кг.

**Поза покоя - стоя, руки опущены вдоль тела, ладони к бёдрам** (не T-поза). Если модель
удобнее скинить в A- или T-позе - скиньте в ней, но перед экспортом поставьте арматуру в эту
позу и примените её как позу покоя (Pose -> Apply -> Apply Pose as Rest Pose).

Оси костей в .glb могут быть любыми (Blender направляет Y вдоль кости, крен - как получится):
`retarget.js` пересчитывает повороты через мировой поворот покоя каждой кости. Закон в
`tests/unit/retarget.test.js` проверяет это на случайных осях.

## Как сделать модель

1. В Blender: `blender --python tools/blender/make_armature.py` - строит арматуру `GoingBoy` из
   `docs/skeleton.json` с переводом осей (демка Y вверх -> Blender Z вверх). Скрипт написан без
   Blender под рукой, его надо проверить.
2. Моделировать тело по арматуре, привязать (Automatic Weights), поправить веса у суставов.
3. Экспорт glTF 2.0 (.glb): +Y Up, только арматура и меш, без анимаций.
4. Положить в `web/models/goingboy.glb`.

## Что должен уметь `body/glb.js` (вид вместо `procedural.js`)

Тот же интерфейс, что у `procedural.js`:

- `create(THREE) -> view`, `view.root` - Object3D для сцены;
- `view.update(f, paths, act)` - `f = kinematics.fk(поза)`: взять `retarget(restWorld, f)`,
  записать `local[имя]` в `bone.quaternion`, `rootPos` - в положение таза; ленты мышц (`paths`) и
  их подсветку (`act`) рисовать поверх меша так же, как сейчас;
- `view.setLayers({ skin, muscles, bones })`, `view.setColors(scene)`, `view.setHover(info)`;
- `view.pickables` - меши для мыши с `userData = { kind: 'muscle' | 'bone' | 'joint' | 'skin', id }`.

Загрузка .glb: `GLTFLoader` из three.js - ES-модуль, а страница работает с `file://` (Electron,
Хаб), где модули запрещены. Его надо собрать в обычный скрипт так же, как `three.js`
(`tools/build-vendor.js`), а сам .glb - отдать через `fetch` из `web/models/` (в Electron с
`file://` это работает; для страницы с диска - встроить как data-URL).

## Что останется проверить с моделью

- Законы ядра не меняются: углы, пол, мышцы, подписи считают по `skeleton.js` и `muscles.js`.
- Подписи не должны налезать на тело: прямоугольники тела для раскладки сейчас - проекции
  капсул кожи; если меш заметно толще капсул, капсулы в `skeleton.js` надо подогнать под него.
